## 1. 不再以旧 Pythonista 单表单作为功能基准

原生代码的真值来源：
- 日常报价、组合报价、资金成本、模板与记录：`MyAssistant/DailyQuote.swift`
- 各品类配方、分项成本及进项税额：`MyAssistant/TenderModels.swift`
- 汽运费规则、历史：`MyAssistant/FreightModels.swift`、`FreightStore.swift`
- 投标、采购和销存：`TenderQuoteViews.swift`、`TenderStore.swift`、`Inventory.swift`

先核对业务模型及公式，再做 UI。SwiftUI 原生界面无法在 Pythonista 中直接运行，须由 `ui.View`、`ScrollView`、分组卡片与控件重建。

## 2. 日常报价必须实现的完整功能

1. 客户历史快捷选择、联系人、微信/电话/现场/其他报价方式、报价时间
2. 四种产品独立编辑与组合报价：道路石油沥青、SBS 改性沥青、乳化沥青、改性乳化沥青
3. 各产品独立规格、数量、拟报价、配方、费用明细与加入组合的开关，切换品类不丢数据
4. 自提/配送、收货地点、最近汽运费引用，自提自动将包含“运费”的成本项置零
5. 分项成本：名称、含税金额、进项税率、备注；可新增费用；道路/SBS 不默认添加包装装车费
6. SBS 配方按“基质沥青掺量=100%-添加剂掺量合计”，添加剂累计超过 100% 时停止保存
7. 乳化和改性乳化的基质材料价格、掺量、税率及额外材料加工费用
8. 先款后货/短期垫资切换，垫资天数与年资金成本率
9. 实时显示直接成本、资金成本、综合成本、每吨利润、毛利率、数量已知时预计总利润，±10/20 快捷调价
10. 微信报价文字模板、模板管理、复制、多品类每行一条；跟进中/已成交/未成交；软删除与审计留痕

## 3. 不能改错的原版计算口径

原生 `DailyQuoteDraft.metrics()` 的日常报价模型：

- `直接成本 = 各成本项含税金额之和 + SBS/乳化配方折算材料成本`
- `资金成本 = 先款后货 ? 0 : 报价 × (年资金成本率/100) ÷ 365 × 垫资天数`
- `综合成本 = 直接成本 + 资金成本`
- `利润/吨 = 报价 - 综合成本`
- `毛利率 = 报价>0 ? 利润/吨 ÷ 报价 ×100 : 0`
- `预计总利润 = 利润/吨 × 数量`，仅数量明确且大于0时展示
- `进项税参考 = Σ[含税成本×税率/(100+税率)] + 配方材料进项税参考`

**重要：Build 93 日常报价利润并不额外扣减进销项税差**；不要错误套用投标模块的税费利润公式。分项税率在日常报价中是进项税信息，和投标税费模型应分开处理。

默认产品：70#A、I-D、PC-2、PCR。默认费用来自 `TenderProductTemplates`，如道路沥青码头费30元/吨(6%)、仓储费40元/吨(6%)；默认年资金成本率4.32%。

## 4. 数据与迁移边界

- 原有 Pythonista SQLite 数据与 API Key 不被远程发布覆盖
- 旧版只存 `direct_cost` 时，迁入成本明细须保留为一条“旧版直接成本（待拆分）”，不得编造历史税率和费用组成
- 原生 iOS App 的应用沙盒和 Pythonista 沙盒相互隔离；**不能承诺自动读取原生 App 的私有历史数据库**
- 用户点击更新 → 下载所有文件 → 验证 SHA256 和大小 → 备份 → 原子替换 → 启动验收；失败回滚
- GitHub 更新采用**完整累积发布**，确保旧客户端跳过小版本也不会漏装修复文件
- 此次优先重构日常报价。投标、销存、日历/AI、文件扫描、快递识别等模块须按各自 Swift 源码单独验收，不能用“报价完成”冒充“整个 App 已完整移植”

## 5. 验收测试

- 同样输入在 Swift Build93 和 Pythonista 计算出的每吨成本、资金成本、利润、毛利率应一致
- 四品类来回切换，各自独立数据不能丢失
- 自提后所有品类的运费归零；配送最近运费只写入当前品类
- 旧版记录升级后不丢、不强制覆盖原有数据
- GitHub 发布文件与清单逐一按实际字节校验，严禁清单领先于实际代码
