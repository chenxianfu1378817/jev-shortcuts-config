## V2.3.2 原生工具库候选

## V2.3.1 登记保存及回执

用户反馈填完登记表后「保存工具」无响应。此前登记操作把表单放入自定义 URL，依赖 WebView 导航回调，且缺少表单内的请求和超时状态。V2.3.1 由 Pythonista 读取本地 WebView 中的登记请求，校验后沿用现有工具库写入逻辑。表单就地显示保存、校验错误、写入错误或超时。保留未保存字段、现有工具库及待回调任务保护。测试执行了页面的保存处理器、临时文件写入及回执渲染；iPhone 尚待复验。

## V2.3.0 恢复原生关闭

用户在 V2.2.9 上确认退出依然无响应。此前测试只覆盖 JavaScript 发出请求，原生窗口是否收到请求及旧忙碌条件是否拦截未能从手机确认。V2.3.0 显示 Pythonista 原生标题栏和系统关闭按钮，移除网页退出和忙碌拦截。窗口关闭后沿用模态返回清理，取消等待中的审批，不改写当前任务。已经交给系统的快捷指令仍可能继续执行。新增测试模拟原生窗口返回及退出清理，iPhone 尚待复验。

## V2.2.9 真机反馈与修复

iPhone 上 V2.2.8 的退出与登记按钮均无响应。退出原先依赖 WebView 的 JavaScript 确认框，登记依赖文档锚点跳转。V2.2.9 直接发出退出请求，登记直接滚动到表单并刷新工具库。已用 Node 执行生成页面的两个点击处理函数并校验发出的请求；仍待 iPhone 验证原生关闭与表单滚动。

## 5. 数据保护、不变量与发布规范

1. 任何时候都**保留** `~/Documents/PYVoiceAgent_Data/` 下真实用户数据，尤其是 `current_task.json`、`shortcut_registry.json`、主题配置、历史记录、DeepSeek 配置及独立业务台账；更新器不可覆盖。
2. 真实或可能真实的“待人工核验 / 待回调 / 暂停 / 正在写入”任务，不自动清理、不强制重做、不因登记快捷指令覆盖。
3. 不将 API Key、录音、电话号码、通讯录或个人记录写入公开仓库。密钥优先系统安全存储。
4. 所有页面遵循统一卡片设计，8 套主题与浅色/深色/跟随系统同步生效，适配 iPhone 键盘、安全区和动态视口。
5. 在线更新遵守旧启动器安全上限、SHA-256、语法检查、失败恢复及用户数据分离；不要通过放宽验证来掩盖超出文件大小。
6. 每次**代码**升级必须递增正式版本与 `sequence`，同步引擎、`manifest.json`、README、测试和本文件；文档编辑**无需**虚构新软件版本。
7. 单元测试/模拟测试/CI 与 iPhone 真机测试分别报告。发布后需远端核对 `manifest` 与源码一致才可称 GitHub 发布完成。
