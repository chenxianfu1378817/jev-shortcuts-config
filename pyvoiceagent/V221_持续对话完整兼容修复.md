# PYVoiceAgent V2.2.1｜持续对话版兼容修复与验收（2026-11-11）

## 来源与修复重点

根据真实 iPhone 截图，V2.1.0 在语音执行时仍关闭 WebView，进入 Pythonista 控制台，使用原生录音弹窗、AI 多轮追问弹窗，重复发送回答后出现规划失败。这是界面生命周期与 AI 交互未统一，不是单纯的卡片样式问题。

V2.2.1 采用 **一个保持打开的本地 HTML/CSS/JS WebView**：文本/语音提交、DeepSeek 追问、AI 续答、执行状态及结果卡片在同一界面；后台 Python 执行，不在正常任务完成后关闭主视图。语音只在用户点麦克风后开始、再点才停止识别，另有独立取消录音，不会按静音自动收音。

## 兼容与原有功能

- V2.1.0 完整业务引擎只追加新会话层，不重写已有 API/提醒/日历/BU 行情/系统写入/导航与防重复机制。
- DeepSeek 文本发送授权和敏感系统写入确认在 WebView 内显式授权；不自动同意。
- 语音任务完成后保留原有简短语音播报。日历及快捷指令有效回调完成后，结果可在新会话里显示，原始任务/历史不丢失。
- “我要点外卖 → 快餐 → 打开美团”由本地白名单处理，尝试唤起安装的美团 App，不调用 DeepSeek、不自动支付或下单、不能保证原生 URI 在每台手机上均有效。
- 首页常用操作“整理剪贴板”“最近结果”已保留；历史可搜索、读取、复制和分享。
- 设置保留八套配色、亮/暗/系统模式、DeepSeek 配置、语音隐私、工具库、模块配置、暂停任务恢复、人工核验、联系人工具、逐步 AI 模式及高级诊断。少数高级配置仍会调用 Pythonista 系统授权界面。
- `PYVoiceAgent.py` 固定入口和 `argv=voice`/`argv=text` 的快捷指令 URL 不改变；首次点击桌面语音按钮打开会话并开始手动录音，**必须用户再次点击才停止**。
- 会话文本保存在 `~/Documents/PYVoiceAgent_Data/chat_transcript.json`（最近 50 条），原有 `history/`、`appearance.json`、Keychain/本地 API 密钥不会被升级覆盖。
- WebView 初始化失败时回退已存在的旧界面。升级器仍检查大小和 SHA-256，保留旧引擎备份。

## 已实际验证的测试

GitHub Actions `pyvoiceagent-v221.yml` 已运行完整 Python 语法编译、持续对话、JavaScript 语法、录音开始/停止/取消模拟、权限确认、AI 追问复用、外卖本地意图、URL 回调、旧设置入口、语音结果播报以及旧版手动录音、地图、结果页、BU 日历回归。

**重要：自动检查是 CPython/JavaScript 模拟环境，不是 Pythonista iPhone 真机测试。** 麦克风、语音识别线程、WebView 持续显示与 iOS 快捷指令跳转，仍需 iPhone 验收。

## 手机更新和首轮验收

继续使用原来的 `PYVoiceAgent.py` → “检查在线更新” → 安装 V2.2.1 → 退出重新运行。

先验证不产生系统写入的操作：
1. 输入“我要点外卖”，再输入“快餐”，最后输入“打开美团”，三条应保留在同一聊天页面，且前两条不会进入 DeepSeek。
2. 点击麦克风手动录音，点击取消录音，确认未自动执行；再重新录音并手动点结束。
3. 提问一个普通文字问题，AI 需要追问时在同一页面用文本或语音补充；执行结束后结果应作为聊天卡片出现。
4. 打开历史、设置、主题及最近结果；查看旧功能入口是否存在。日历、提醒写入等真实系统操作应在只读流程成功后再测试，防止意外重复创建。

如因 Pythonista/iOS 生命周期导致异常，保留控制台截图和当时具体操作步骤，不能因离线测试通过而宣称真机必定不崩溃。
