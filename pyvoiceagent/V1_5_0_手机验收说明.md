# PYVoiceAgent V1.5.0 手机验收版 — 升级及验收

当前 main 的 `pyvoiceagent/manifest.json` 指向 V1.5.0（sequence=150）；V1.4.3 的源代码依然保留，原来的 `PYVoiceAgent.py` 永久入口、Pythonista Keychain、数据目录、PYAgentHub、PYAgentNotes、PYAgentCalendar 全都不需要更换。

## 重要排障：旧版菜单第 16 项报 NameError

如果 Pythonista 控制台显示 `NameError: name 'print_update_status' is not defined`，且 traceback 指向 `~/Documents/PYVoiceAgent_Data/engine/current.py` 的 **第 1075 行**，经 GitHub 源码逐行核对，这是 **V1.4.1 引擎** 中 `show_menu` 调用缺失函数的问题，而**不是 V1.5.0 的该函数缺失**。V1.5.0 源码中已定义该函数。

旧版缓存中 V1.4.0、V1.4.1、V1.4.2、V1.4.3 的菜单“检查更新状态”都有这一缺陷；因此**不要再使用旧版引擎菜单第16项检查更新**。原 `iCloud/PYVoiceAgent.py` 固定入口里的更新器是独立实现，非回调模式下会检查 GitHub manifest。

故障时先在 Pythonista Console **只读检查**：

```python
import os, json
b = os.path.expanduser('~/Documents/PYVoiceAgent_Data')
m = json.load(open(b+'/update_meta.json')) if os.path.isfile(b+'/update_meta.json') else {}
t = json.load(open(b+'/current_task.json')) if os.path.isfile(b+'/current_task.json') else {}
print('已下载版本:', m.get('installed_version'), '最近更新:', m.get('last_result'),
      '禁用版本:', m.get('broken_version'), '任务状态:', t.get('status'),
      '存在待执行回调:', bool(t.get('pending')))
```

不要因为显示旧版就直接删除 `engine/current.py`、`current_task.json`、`update_meta.json`。先根据检查结果判断是检查间隔未到、先前故障回退、还是因为尚有不确定系统写入被阻止更新。只有确认无待核验系统写入，才按下方“重置 last_checked”步骤请求重新检查。

## 一、先打开原来的 PYVoiceAgent.py

- 看到菜单标题 `PYVoiceAgent V1.5.0` 说明当前执行的版本已更新，可以跳过下一段。
- 如果仍是 V1.4.3，固定入口默认每隔 6 小时、并且仅在主动运行时检查自动更新。可以等待自然更新；或在 Pythonista Console 中运行下方仅重置 **last_checked 检查时间** 的代码（不会清空 Key、历史任务或备忘录）：

```python
import os, json
p = os.path.expanduser('~/Documents/PYVoiceAgent_Data/update_meta.json')
d = json.load(open(p, encoding='utf-8')) if os.path.isfile(p) else {}
d['last_checked'] = 0
os.makedirs(os.path.dirname(p), exist_ok=True)
with open(p, 'w', encoding='utf-8') as f:
    json.dump(d, f)
print('已准备好重新检查更新。请关闭控制台并重新运行原来的 PYVoiceAgent.py')
```

- 若提示“存在待核验的跨 App 操作，本次不更新”，固定入口为了防止任务重放而停止升级。旧版 V1.4.3 下需要**最后一次**在菜单第 11 项处理已实际检查过的旧任务。对于此前那条用户已确认并未创建的综合测试备忘录，请选择“亲自确认没有创建”；**如果未检查过，不能猜测或跳过**。然后重新运行原脚本。
- 不要手动删除 `current_task.json`、`update_meta.json` 或重新设置 DeepSeek Key。
- 若显示版本还是 V1.4.3，或更新失败，不要继续后面的首次模块登记。

## 二、先启用苹果备忘录模块

1. 进入 V1.5.0 菜单 **17. 首次安装/验证系统模块**。
2. 选择“苹果备忘录 PYAgentNotes”。
3. 允许创建一条标题为“PYVoiceAgent模块验收测试”的真实测试备忘录。程序应该启动已有的 `PYAgentNotes` 并自动回调。
4. 收到回调后程序会询问“模块安装验收”。先到苹果备忘录打开刚创建的这条测试笔记，确定正文正确，再返回 Pythonista 选择“我已经亲自确认测试项目存在”。
5. 如果没有创建或不知道有没有创建，应选择“尚未确认或项目不存在”，此模块仍然关闭，不要重复运行创建测试。

## 三、再启用日历模块

重复菜单第 17 项，选择“苹果日历 PYAgentCalendar”。系统会发起一条 4 天后的下午 14:00–14:30（按 iPhone 本地时区生成）的测试事件。到苹果日历核对标题、日期、起止时刻和备注准确后再确认。若任何字段错误，不要勾选验收成功。

## 四、查看模块状态，进行双任务验收

1. 菜单第 10 项查看系统工具，`PYAgentNotes` 和 `PYAgentCalendar` 应均标记“已验收启用”。
2. 菜单第 2 项“手动输入任务（AI）”，可输入：
   “请创建一条苹果备忘录，标题‘语音助手联调记录’，正文‘已完成系统接口测试’；随后在后天15:00–15:30创建苹果日历事件‘语音助手联调日程’，备注‘验证两项连续执行’。必须按实际结果逐项汇报，没有核实的项目不要声称核实。”
3. 分别同意每次系统写入请求。快捷指令回调应推动程序规划下一项；若出现待核验、失败或意外重复，请停止并保留截图。
4. 到苹果备忘录和日历各自确认真实写入；测试数据可在验收结束后手动删除。
