# V1.7.1｜复制 PYAgentCalendar 改成日历查询（最小修改）

**原有 PYAgentCalendar 不改动；不修改《我的助手》；不新增 PYAgentHub 菜单。** iPhone 只需在「快捷指令」中复制已通过真机测试的 PYAgentCalendar，重命名为 **PYAgentCalendarRead**。

## 保留不改的部分

顶部的「快捷指令输入 → Base64 解码 → 从输入取得词典（任务词典）」及读取 `token`、`start`、`end` 的动作、日期转换动作均保留。若副本有检查 route 的“如果”条件，从 `calendar.create` 改成 **`calendar.list`**。

## 仅修改中间查询动作

1. 移除副本里的「添加新日程」动作（不要改原版）。
2. 添加苹果「**查找日历日程**」。条件：**开始日期介于**此前从词典读出的 `start` 和 `end` 两个日期变量；按开始日期升序，开启数量限制，最多 **8 项**。苹果快捷指令有 Find Calendar Events 查找和筛选能力，首次运行可能询问访问日历权限。
3. **如果查找结果数量为 0**：将待回传文本设为**两行**：第一行严格 `CALREAD1`，第二行 `0 项日程，查询范围内没有结果`。
4. **否则**：对结果「重复每一项」，用该日历项目的**标题、开始日期、结束日期**组成一行文字（例如 `10-18 09:00—10:00 项目会议`），「添加到变量 日程列表」；最后「合并文本」用换行隔开，并在最前面添加一行 `CALREAD1`、第二行 `查询成功（最多显示8项）：`。不要把固定文本 `CALREAD1` 拼成单行，也不要有前导空格。
5. 不要使用通知、提醒或创建动作，也不要把完整日程数据在网页上传。

## 修改最后的成功回传

原来仅回传 `token` 和 `ok`；现在需要第三个参数传查询正文。对上一步的完整待回传文字依次执行：

- 「Base64 编码」（设置为**无换行**）→「URL 编码」，记为 `已编码查询结果`。
- 使用原来的回调 URL，末尾增加一个 URL 参数：
  `&argv=[已编码查询结果]`

完整回调模板（中括号文字需在快捷指令编辑器里替换为动态变量，不是字面输入）：

`pythonista3://iCloud/PYVoiceAgent.py?action=run&argv=bridge_callback&argv=[token]&argv=ok&argv=[已编码查询结果]`

若原有 URL 已有动态 token、status，则原部分完全保留，只增最后 `&argv=...`。失败时不可只返回 `ok`，否则 PYVoiceAgent 会停下并要求核验。

## Pythonista

V1.7.1 已在原仓库 `pyvoiceagent/manifest.json` 激活；原固定入口 `PYVoiceAgent.py` 首页选「4. 立即更新版本」。不用登记新的自定义工具，也不改已有 `PYAgentCalendar` 的创建回调。用户说“查询明天的苹果日历安排，只查询”，DeepSeek 选择 `calendar.list`，Pythonista 直接运行 `PYAgentCalendarRead`，等待匹配 token 且结果以 `CALREAD1\n` 开头的 Base64 回调。**若只有 ok 没有正文，会拒绝报告“没有日程”**。

第一次只测试一天内已有事件的纯查询；若回调成功，完整结果显示在 Pythonista 控制台和上次执行记录中。更复杂的「查询后让 AI 分析冲突」仍需基于真机读回继续验证，不要以此版本已经全面验收。

**离线验证**：11 项新回调/安全测试 + 23 项 V1.7 原功能 + 41 项 V1.6.2 + 80 项旧版，合计 **155 项**。真机快捷指令尚待用户复制、修改并验证。
