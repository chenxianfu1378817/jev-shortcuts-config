# PYVoiceAgent V2.2.0｜持续对话、手动语音与控制台返回修复（2026-11-11）

## 真机反馈所揭示的问题

V2.1.0 虽以本地 WebView 显示首页，却在选择“语音执行”后先关闭 WebView，再调用 Python 原来的 `dialogs.alert()` 录音/AI 追问和控制台输出。因此用户在一轮任务中看到了 Pythonista Console、重复弹框和连续追问，最终部分任务回到控制台。

## 本次实现

- 首页进入一个持续存在的、完全离线的 HTML/CSS/JavaScript WebView 对话视图。正常任务执行不再关闭它；任务运行在 Python 后台工作线程，界面在同一视图追加消息、结果卡及状态。
- 麦克风按钮由用户手动启动，**再次点击才停止录音并识别**；页面提供“取消本次录音”单独按钮，取消会丢弃录音而非执行。没有基于静音时间自动停止。
- DeepSeek 要求补充信息时，问题显示为助手聊天气泡，用户在同一个输入框或麦克风回答。由原工作线程继续原任务，不另建新任务、不重复规划已执行系统动作。
- 需要上传文字、修改提醒/日历等敏感操作时，在相同页面提供明确授权按钮；未授权不得自动执行。已保存的“今后允许发送文字”设置仍沿用本地配置。
- 对不涉及购物支付的简单指令做有限白名单本地路由：“我要点外卖”→询问类型；“快餐”→建议打开外卖 App；“打开美团”→尝试 `imeituan://`；“打开美团外卖”→尝试 `meituanwaimai://`。**只尝试启动本机 App，不自动下单、不称已经打开或支付成功。** 未经 iPhone 验证的 URI 可能不可用。
- 历史档案、搜索、主题、浅色/深色、检查更新入口仍在同一个 WebView 中；全部界面 HTML/CSS/JS 内嵌在 Python 引擎，可离线加载，无外部 CDN。
- 桌面原有 `argv=voice`、`argv=text` 改为先打开持续对话页，再执行对应明确用户入口；匹配的快捷指令回调在完成后从原状态文件恢复结果到对话页，其他不相关回调不弹出界面。
- 会话 UI 的最近 50 条文字保存在 `~/Documents/PYVoiceAgent_Data/chat_transcript.json`，不上传 GitHub、不覆盖旧任务/历史/凭据。结果详档仍由原有历史模块保存。
- 保留 V2.1.0 所有原业务引擎，包括 BU 行情日历、日程只读/创建、提醒事项、备忘录、导航、DeepSeek、Keychain、统一主题和失败保护。
- WebView 初始化失败时清理会话后恢复 V2.1.0 界面；用户数据不作不可逆迁移。

## 技术和安全边界

1. WebView 只允许 `pyagent-chat://dispatch` 的动作白名单、随机 nonce 和限定长度。HTML 使用无网络 CSP；显示用户/AI 文本使用 `textContent`，不当作可执行 HTML。
2. Python 工作线程负责规划；Pythonista 原生 `ui.delay` 用于把状态送到 WebView UI 线程。敏感操作继续由原引擎校验，回调 token 与原防重复保护未修改。
3. 界面关闭会解除待答复/授权的等待，不会自动重放系统写入；无法保证 iOS 挂起时后台线程继续执行。
4. 第三方 App URL Scheme 来源并非应用官方稳定性保证，只能显示“发起请求”，不能保证安装或成功跳转。
5. 这不是独立签名的 iOS 应用；仍依赖 Pythonista 执行。

## 更新与手机验收

原入口 `PYVoiceAgent.py` 不改。打开既有应用 → “检查在线更新” → 安装 V2.2.0 → 退出重新运行原入口。

建议先在新对话界面输入 **“我要点外卖” → “快餐” → “打开美团”**，应看见对话气泡和一个原生 App 启动尝试，而非 AI 连续弹窗；随后测试麦克风开始/停止、取消录音、普通文字任务、AI 追问和日历只读回调。**不要用真实创建多条提醒或日历的指令进行首次回归，以免重复写入。**
