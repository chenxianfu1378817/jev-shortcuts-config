# PYVoiceAgent V2.2.3｜修复停止录音时的闪退风险（2026-11-11）

## iPhone 真机反馈

V2.2.2 对话界面中：点击麦克风开始录音 → 说话 → 再次点击麦克风停止 → Pythonista 闪退。没有 iOS 崩溃堆栈，**尚不能断言唯一根因**。

## 源码定位与处理

V2.2.2 旧代码在 WebView 自定义 URL 的 `webview_should_start_load` 回调中**直接**调用 `sound.Recorder.stop()`，并立刻使用 daemon 线程调用 `speech.recognize()`。两个时机可能与 WebKit 导航回调、原生音频对象释放及录音文件写入发生竞争。Pythonista 官方示例在停止录音后才调用 `speech.recognize()`，没有在导航回调中停止原生录音。

本次 V2.2.3 采用针对性修复：
- WebView 麦克风的「开始」「结束」「取消」动作都用 `ui.delay` 排队，先结束 WebView 导航委托事件，再操作原生 `sound.Recorder`。
- 停止时锁定本次录音状态，连续快速点击仅执行一次 `stop()`，禁止录音尚未识别完成就再次开麦。
- `stop()` 返回后先释放 Recorder，再延迟约 0.7 秒等待文件完成写入、界面刷新，然后按照 Pythonista 官方示例在主线程开始语音识别，而不是立即开一个 daemon 子线程。
- 录音停止失败时**不调用**识别、不执行原任务；向对话界面反馈失败，清理临时音频。
- 点击取消只停止并删除文件，不识别、不调用 AI。关闭界面也不会在延时任务中重新识别。
- 新增本地诊断 `PYVoiceAgent_Data/voice_last_stage.json`，只记录版本、时间和阶段（如 `stop_enter`、`audio_stopped`、`recognizing`），**不会保存录音内容或识别文字**。若仍闪退，可据此判断进入了哪个阶段。
- 其他 V2.2.2 的 WebView UI、持续聊天、AI、日历、提醒事项、BU 行情、主题、在线更新和本地数据原样保留。

## 发布兼容

- 使用新的正式引擎文件 `agent_core_2_2_3.py` 和递增更新清单 `sequence=223`，固定入口 `PYVoiceAgent.py` 不变。
- **沿用 V2.1.0 的 350000 字节上限和完整 SHA-256 校验**，保持失败回退路径；不强行下载 ZIP，不修改历史配置。
- 测试文件 `tests/test_audio_stop_v223.py`：9 项隔离模拟覆盖延时停止、连点去重、录音文件释放、语音识别成功/失败、取消、不重复任务、关闭页面及发布校验。GitHub CI 同时运行旧版语音/AI/地图/BU 日历回归测试。

## 测试与风险边界

GitHub Actions 的测试是 Python/mock 与 JavaScript 层模拟，**不是 iPhone 原生麦克风或 WebKit 真机测试**。实际 iOS `Recorder.stop()` 与 `speech.recognize()` 仍可能因 Pythonista 或系统音频权限/会话状态产生原生崩溃。语音识别运行在 UI 线程，识别期间界面可能暂时不响应；这是为优先规避原线程生命周期问题采取的保守调整。

## 手机验收

先用原软件「检查在线更新」升级至 V2.2.3；关闭并重新运行固定入口；只测试一句不带系统写入的语音，例如「你好」，点击麦克风开始录音 → 说话 → 点击麦克风停止。查看是否能显示识别结果和回复。随后测试「取消本次录音」不会执行任务。若依旧闪退，不要重复尝试真实日历/提醒写入；重启后可查看本地 `PYVoiceAgent_Data/voice_last_stage.json` 的最后 `stage` 值及截图，以定位下一步修复。
