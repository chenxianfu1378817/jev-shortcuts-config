## 手机更新流程

1. 直接使用你已有的桌面语音入口，或在 Pythonista 打开固定脚本 PYVoiceAgent.py。
2. 如果程序自动更新间隔未到，可在首页点 **「检查在线更新」**。检查通过后退出重新运行，让新版引擎生效。
3. 首次进入新首页，通过 **「设置与工具 → 外观与主题」** 选择颜色/显示模式。
4. 如果提示有待核验的跨 App 操作，先在苹果 App 中核对后再处理，不能为了更新直接删除任务状态。

## 安全与限制

- GitHub 仅发布程序、清单、测试和说明；**不上传 DeepSeek API Key、录音、联系人、真实任务或个人配置**。
- 下载后会检查版本、长度、SHA-256 与编译语法；本地保留历史引擎，失败时不自动重复系统写入。
- SHA 与程序清单同仓库，并非独立签名；保护依赖 GitHub 仓库权限和更新源安全。
- iOS 部分第三方功能仍需首次导入快捷指令或用户授权，不能以 Python 自动绕过系统限制。
- **真机需验收**：未在你的 iPhone 上实测新界面；离线代码/模拟测试不等于真机测试。

## V1.9.3｜BU 日盘、夜盘自动写入苹果日历

- 沿用同一条 Pythonista 固定入口及 day/night URL；行情读取成功后先保存 TXT/JSON，再通过**已验收的 PYAgentCalendar** 创建苹果日历日程。

- 单独保存 `bu_futures/calendar_ledger.json` 进行同日/时段防重、回调核验和失败保护，不覆盖语音任务 `current_task.json`。
- 日历模块未授权时不强行创建；原行情档案继续保留。
- `bu_close&argv=test` 仅保存测试快照，`bu_close&argv=test_calendar` 经用户确认后创建测试日程。
- 详见 [BU 日历自动归档操作与验收](BU_日历自动归档_V193.md)。

## V1.9.5｜按用户要求：BU 行情每次采集都请求写入日历

- 解除 BU 专用流程的「今天已经写过」拦截，也不再要求先登记本地模块验收标记。
- 每次日盘／夜盘执行都生成独立 token 和新日历创建请求，**会产生多条相同日期的事件**；用户主动选择此行为。

- 保留旧的 calendar_ledger.json，并为每次新请求单独记录流水。普通 AI 任务的系统写入授权规则不变。
- 既有 day / night 定时 URL、桌面入口与本地 TXT／JSON 保存均不需要更改；普通 test 仅保存报价，不创建日程。
