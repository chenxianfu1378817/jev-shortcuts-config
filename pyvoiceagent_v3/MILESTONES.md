# V3 分层重建设计与发布门禁

版本状态：**V3 Alpha 0.1.0 / 开发基线**。原 V2 GitHub 正式更新清单保留 V2.3.9，不动用户手机数据。

## 采用的最终技术路径

1. **核心**：标准 Python 包 + SQLite + 明确的依赖注入。独立管理 DeepSeek、任务、工具注册、存储和历史；不导入 Pythonista/Swift/JavaScript 的 UI SDK。
2. **当前 iPhone 测试入口**：仅使用单次 Pythonista 控制台或苹果快捷指令调用已验证的动作；先让任务引擎稳定，再考虑界面。不得继续用长生命周期的 `ui.WebView`/URL 导航作为任务引擎消息队列。
3. **未来完整原生客户端**：SwiftUI 小客户端（需真实签名与安装）与 Python/服务端采用明确版本化协议。**不强行将 API Key 放在网页 JavaScript 里，也不宣称 PWA 能无授权执行日历/提醒。**
4. **可选免签名界面**：浏览器/PWA 只能做前端，后端必须经身份验证并支持离线状态及重试；本机系统动作需要已授权的快捷指令交接。是否适合长期使用须单独评估。

## 分层验收门槛

- **A（当前）：纯 Python 核心**：桌面自动测试 100% 通过，故障注入、并发、数据保留和回滚有证明；保留 V2 代码和入口。
- **B：同 iPhone 极小入口**：不调用 AI、没有 WebView/音频，在相同设备验证 20 次冷启动、50 次短文本输入、打开/关闭历史与设置、前后台切换、无崩溃后才可扩展界面。不能把 Mac 模拟当手机通过。
- **C：只读 AI**：首次向 DeepSeek 发送文字前显示明确授权，测试无网、超时、错误码、空结果、重复点击与退出后回执；不得静默重试。
- **D：系统工具**：先只读日历、再逐个开放提醒/快捷指令写入；真实动作逐项回读确认，重复请求同一个 ID 不得执行两次。
- **E：发布迁移**：本地数据备份、V2 导出结构验证、dry-run、失败可回滚、GitHub 正式清单与发布字节一致；只有 B–D 真机验收后才能考虑替换旧入口。

## 需要保留的外部崩溃证据

手机：设置 → 隐私与安全性 → 分析与改进 → 分析数据。若有 Pythonista 相关 `.ips`，优先看 exception type、thread triggered、相关 native stack；共享之前删去设备标识、地址、私有文本和密钥。不要根据某一条 Python 日志就宣称 C/Objective-C SIGSEGV 已根治。
